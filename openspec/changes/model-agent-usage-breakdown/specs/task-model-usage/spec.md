# Spec Delta

## Purpose

让用户在当前任务的消耗界面中区分不同模型与执行角色的 Token 用量，同时明确数据来源覆盖范围和不可归属的部分，避免误读。

## ADDED Requirements

### Requirement: 按模型显示当前任务消耗
系统 SHALL 在任务消耗下方显示可可靠归属的模型 Token 明细，统计单位与现有任务消耗一致，不显示为金额。

#### Scenario: 当前任务使用多个模型
- **WHEN** 当前任务中有可可靠归属的两个模型的用量记录
- **THEN** 界面分别显示两个模型的名称和各自的 Token 消耗

#### Scenario: 模型发生切换
- **WHEN** 同一任务中模型切换且每次调用可可靠关联模型
- **THEN** 各次调用计入各自模型，而不全部归给当前选中的模型

### Requirement: 区分主会话与子代理
系统 SHALL 基于可验证的线程关系区分主会话与属于当前任务的子代理，并按模型展示其可归属的用量。

#### Scenario: 子代理使用模型
- **WHEN** 能确认子代理属于当前任务且其模型与用量可关联
- **THEN** 界面将其标识为子代理，并显示其模型和消耗，不与主会话混淆

#### Scenario: 无法确认父子关系
- **WHEN** 记录的父子线程关系无法确认
- **THEN** 系统不得将该记录认定为当前任务子代理或计入其明细

### Requirement: 明确不可归属及覆盖限制
系统 SHALL 不推测未知模型或角色，仅当未知部分可可靠计量时才显示其数值；明细不可用时在面板内显示不可用状态，覆盖不完整等说明 SHALL 通过面板的无障碍标签提供，不占用可见行（2026-11-25 用户决定：面板只保留模型 ID 与数字，不显示描述文字）。

#### Scenario: 部分调用缺少模型
- **WHEN** 已知属于当前任务的用量记录缺少可靠模型标识
- **THEN** 界面将其标为未知模型，不将其分配给其他模型

#### Scenario: 缺少可归属明细
- **WHEN** 数据源无法提供可靠的模型或子代理明细
- **THEN** 界面显示明细不可用（可见），或把覆盖不完整写入面板的无障碍标签，不以零或完整数据冒充未知值

### Requirement: 保持任务总数口径
系统 SHALL 保留现有任务消耗总数的计算口径；明细覆盖范围与总数不同或无法核对时，说明 SHALL 通过面板的无障碍标签提供，不新增可见说明行。

#### Scenario: 明细与总数覆盖范围不同
- **WHEN** 任务总数和模型明细来自覆盖范围不同的数据
- **THEN** 保留原任务总数，并把可能无法与总数相加核对的说明写入面板的无障碍标签

### Requirement: 不重复计量调用
系统 SHALL 防止同一次可识别调用因实时和历史记录重叠或重复记录而被重复计入明细。

#### Scenario: 重放的调用记录
- **WHEN** 同一次可识别调用重复出现
- **THEN** 该调用在模型及角色明细中仅计入一次
