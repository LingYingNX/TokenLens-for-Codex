# Proposal

## Why

当前任务消耗只有总 Token 数，无法区分会话使用的不同模型或子代理。需要在不伪造归属的前提下，让用户看清各模型和执行角色的消耗。

## What Changes

- 在任务消耗下方增加当前任务的模型消耗明细，使用 Token 数而非金额，区分主会话与可确认的子代理。
- 仅对可证实的模型、线程和调用进行归属；数据缺失或覆盖不完整时明确提示，不将未知归属猜作已知模型或主会话。
- 保留现有任务总数口径，明细覆盖范围与总数不一致时明确说明，不伪称两者必然相等。
- 复用现有允许的数据来源和本地只读记录，先验证模型与父子线程关联是否可得；不能可靠实现的部分以不可用状态呈现。

## Capabilities

### New Capabilities

- `task-model-usage`: 当前任务按模型和主会话、子代理区分的 Token 消耗及覆盖情况。

### Modified Capabilities

无。

## Impact

涉及 `tokenlens.js` 的用量聚合和弹层、可能涉及 `standalone/rollout-history.mjs` 与宿主桥接、现有 Node 测试及文档。现有 Magpie 汇总和本地历史接口的模型字段及子线程关联能力需以实际记录验证；不引入新的外部服务。
