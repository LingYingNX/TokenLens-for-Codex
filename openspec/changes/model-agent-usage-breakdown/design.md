# Design

## Context

现有任务总数由 Magpie 当前线程查询与本地实时数据按既有规则组合；Magpie 快照解析只保留总量，不能作为模型明细。`standalone/rollout-history.mjs` 使用当前线程 ID 搜索 rollout，输出每次调用用量，但未输出模型与父子线程关系；实际记录是否提供这些关联尚未证实。现有宿主及官方脚本环境的来源能力也可能不同。

## Goals / Non-Goals

**Goals:**
- 保留原有总数，新增独立、可追溯且明确覆盖限制的明细。
- 兼容无模型字段、无子线程或宿主不支持的情况。

**Non-Goals:**
- 不提供费用估算、账户账单对账、跨会话全局统计或新的外部网络服务。
- 不修改现有任务总数口径，不靠当前模型选择推断历史模型。

## Decisions

1. **用调用级证据归属而非拆分现有聚合总数。** 首先以脱敏或合成数据核实 rollout 与现有 Magpie 请求结果中模型、调用 ID、线程关系的字段和关联语义；仅在证据充分时读取相应信息。替代方案是按当前模型或总数比例推算，但不可靠。
2. **独立于原总数聚合。** 明细按已确认的线程角色和模型聚合去重后的单次调用，以现有 token 口径计数。对无法可靠计量的差额只提示覆盖限制，不以总数减法伪造未知用量。实时与历史能稳定匹配才合并，否则仅使用可去重来源并标明覆盖局限。
3. **显式区分不可用与零。** 用独立状态表示加载、部分覆盖、不可用；仅有可靠数量时显示未知模型数值。查询失败不破坏原任务消耗显示；切换线程时丢弃旧线程异步结果。
4. **宿主能力渐进增强。** 对现有历史接口只做向后兼容的可选字段扩展，必要时在允许的宿主只读本地记录范围内增加关联；旧宿主缺字段即显示受限，不要求所有宿主更新。仅遍历可验证归属当前任务的子线程，限制扫描和缓存规模，不记录敏感原文。具体证据若不足，则不猜测关系。
5. **沿用现有紧凑弹层。** 在任务消耗项下放置模型与角色明细；动态名称以 textContent 渲染，长名称可截断并保留可访问名称。

## Risks / Trade-offs

- [记录没有可靠模型或父子关联] → 明确显示不可用或部分覆盖，禁止根据时间邻近推断。
- [任务总数与明细时间范围或数据源不同] → 分别说明口径，不承诺相等，也不把子代理盲目加入原总数。
- [大 rollout 或子线程扫描成本高] → 利用既有加载时机、限制并发与数据保留；不在高频实时路径扫描全量历史。
- [历史及实时重复或切线程串数据] → 依据可靠身份去重，无法判定时不合并，添加线程切换及重复回归测试。

## Migration Plan

新增字段为可选，旧数据与旧宿主回退为受限状态，无需迁移用户数据。撤回时恢复脚本及宿主对应版本；不修改 rollout 文件。
